## 2. 元选项的含义与 P7 可学习的范围

“可证明更强结果”的元选项，指向的是**其他选项与可证明结论之间的关系**，不是又列出一个具体数学公式。

教学例子（非真实题目）：假设某方程在题设条件下能证明“恰好有一个解”。具体选项只给出“至少有一个解”。后者是真的，却比“存在且唯一”弱。如果另一选项说“其他选项中有正确陈述，但可证明更强结果”，它可以代表这个未直接列出的强化结论。

因此不能只理解成“范围太狭窄”。弱化还包括丢失唯一性、只给出充分条件而非等价关系、给出较松的界、删除最优性或端点。反过来，字面更强不一定为真，选项也可能故意过度断言。

LiveMathematicianBench 论文第2节描述了用该元选项替换部分题目的原正确选项的构造方式。它是当前基准的一项公开构造特征。**基准先验与数学证明是两种不同的知识类型**，不能混称。

P7-R2 不再用正则表达式把所有元选项偏好建议一律拒绝。允许 Learner 从本轮合法 Train 经验中提出 `benchmark_prior`；若它只是公开题型上的经验倾向，就如实标记，不宣称证明了定理。仍然禁止任务ID→答案、固定字母答案表、把 Test 的逐题标签或55题统计灌进 Learner。外部完整 SkillOpt/SkillOpt-Lite 文本只用于人工对照，不偷偷导入 Ours。

## 4. 唯一候选合同：去掉 scope 与条件的双重权威

在现有 `math_effect_contract.py` 增加显式 R2 分支。旧 VERSION 和旧读法保持不变，新身份建议 `livemath.effect-evolution.p7.r2`，不要改一个全局常量让旧运行无法恢复。

### 4.1 新 Candidate 核心结构

```json
{
  "category": "maximality",
  "goal": "学习器生成的实际决策目标",
  "applicability": {
    "mode": "all_tasks",
    "require_all": [],
    "exclude_any": []
  },
  "steps": ["学习器生成的具体操作"],
  "stop_condition": "局部规则不适用时回退正常推理，最终仍提交一个合法选项",
  "rule_basis": "reasoning_procedure",
  "source_case_ids": ["实际Train来源"],
  "edit_rationale": "来自真实经验的可检验假设"
}
```

| 字段 | 类型及含义 | 必须处理的边界 |
|---|---|---|
| category | 非空短字符串，描述操作 | 不再用有限算法枚举限制可学数学策略 |
| applicability.mode | `all_tasks` 或 `when` | all_tasks的两个列表必须为空；when至少有一个正向条件 |
| require_all / exclude_any | 公开特征名的字符串列表 | 先检查成员是string，再集合运算；正负条件不能矛盾 |
| steps | 非空字符串列表，1–8步 | 内容由Learner生成；不要求已经具备数学证明 |
| rule_basis | `reasoning_procedure`、`benchmark_prior`、`mixed` | 确定内容身份，不据此阻止普通探索 |
| source_case_ids | 1–60个不重复的真实Train物理ID | 允许单来源提出候选；只有多来源证据才能报告跨来源归纳 |
| stop_condition | 非空字符串 | 停止的是局部规则，不是停止提交整题答案 |

新合同不再保留独立顶层 `scope`。全局/局部统计由 `applicability.mode` 派生，避免两个字段反复打架。正文预算维持当前600 tokenizer tokens的运行时注入上限；本轮不再向下压缩。源材料和模型响应不受这个运行时上限代替。

### 4.2 旧候选迁移和定向修复

对 `global + [comparable_conclusions]` 的历史候选，保留原始响应。Host可以做**可证明等价的合同迁移**：若在当前输入合同中多选题始终具备多个选项，唯一条件仅为 `comparable_conclusions` 且无排除条件，它是冗余输入检查，可迁移到 `all_tasks`，并记录为 `contract_equivalent_migration`，不是新自然生成或新提分。

若条件涉及 scope/量词/元选项等非恒真特征，不能静默删掉。把原候选、具体field_path和两种合法表示交给一次定向修复，请模型确定是 `when` 还是 `all_tasks`。已合法的其他候选原样保留。超过注入长度的候选只修过长部分，不丢整个batch。

### 4.3 编辑采用完整替换对象，而不是混合类型的补丁指令

当前 `apply_edits()` 只允许对字符串和steps下标操作。R2采用更简单的声明：

```json
{
  "decision": "edit",
  "edits": [{
    "parent_id": "真实候选ID",
    "replacement": {"这里使用": "完整、同一份Candidate Schema"},
    "rationale": "此次修改解决哪个已观察问题"
  }]
}
```

示例中的 replacement 必须替换成上节完整Candidate，不是允许任意字典的Schema。`no_change` 单独一条合法分支，不要求edits。每次最多两个候选替换。Host计算diff与新ID，模型不能指定新hash、state、效用收据或publication状态。

允许修改 goal、applicability、steps、stop_condition、rule_basis；来源只能引用已经给当前Learner的Train材料。修复类型/字段的请求最多一次，独立计入 `structural_repairs`，不占最多两轮的 `substantive_edits`。全部HTTP照实计费。

## 5. 实质学习循环：少量真编辑，不再花绝大部分钱检查一个候选

默认只运行下面的有限循环：

1. 读取全部Train60并保留已有局部量词候选；修复全局候选；一次归纳形成不超过3条互补Atomic。
2. 组成一个初始policy：最多一个全局策略和一个适用局部策略，仍为一次主要LLM解题。
3. 在固定Train12上运行NoSkill及该policy，记录真实干预与元/非元分组。
4. 根据真实反馈进行最多两轮实质编辑；每轮评估一个完整policy版本，不展开所有组合暴力搜索。
5. 保留被测试的所有版本和当前最优候选；冻结一个 `experimental` 版本直接观察Val17，不要求先过“净增2才允许继续”的许可门。

最多3个policy版本做完整反馈求解；最多一个NoSkill基线批次。源策略完全没有合格候选时如实报告 `no_candidate`，不得手工写一条冒充自然学习。一次no_change只表示这一编辑没有产生新内容，不等同于整个方法或模型无能力；剩余次数内可用同一反馈提出不同假设。

新Inducer/Editor提示词必须包含：比较所有选项；区分真但较弱与无依据更强；可以学习基准经验先验但标记身份；错误原因是待检验假设；保存本来成功的判断；没有新事实不要无理由改答案；停止局部方法后继续正常解题并提交合法label。不要要求输出完整证明，亦不要要求把策略改成Python。

## 6. 效果归因：相同请求的两次波动，不是Skill造成的改变

`math_effect_optimizer.pairs()/receipt()/verify_receipt()` 使用同一个版本化统计函数，不再让验证器硬编码另一套不同阈值。

每个配对至少补充：

```json
{
  "physical_key": "当前题ID",
  "on_selected_ids": [],
  "off_wire_hash": "主请求语义内容与生成参数的hash",
  "on_wire_hash": "主请求语义内容与生成参数的hash",
  "intervention_applied": false,
  "meta_option_present": false,
  "off_correct": true,
  "on_correct": false,
  "outcome": "loss",
  "attribution": "same_policy_sampling_difference"
}
```

- 比较实际发送的题目、选项、提示、工具表面与生成参数；run目录、request_id等旁路审计字段不构成策略干预。
- 同时报告全量成绩、实际干预子集、未干预子集，以及meta/non-meta四种切片。没有注入但外层prompt不同也算干预，不能只看selected_ids。
- 对未干预的变化，两个方向对称处理：不把变对归功Skill，也不把变错认定为Skill退化。
- 实际干预子集的胜负仍有随机性，只是更相关的反馈，不是单题因果证明。
- 本轮**先不增加跨臂共享响应缓存**，避免再引入缓存身份/费用问题；保留两个真实臂。未来若采用共享NoSkill，必须预先声明、显示引用原响应并只计费一次，不能冒充两次独立执行。

Editor材料补充 `selection`、`intervention_applied`、实际策略全文、公开题干和选项、提交、正确性、finish状态及分组结果。缺过程的题用 `diagnosis_status=hypothesis`，不能臆造“第一处推导错误”。未干预题可以说明模型不稳定，但不当作修改某条Skill的直接证据。

排序主要看实际干预净修复数量、干预退化数量，再参考全量准确率和真实成本；同时保留候选相对于当前incumbent的对照。不能只用小子集百分比挑一个覆盖很低的策略。没有正向收益就标记 `no_observed_gain`，但仍允许冻结实验候选去完成已授权的Val观察；不伪造 `qualified=true`。

## 7. 元选项检测：只检测公开选项身份，不替模型偷偷答题

旧 `features()` 的regex还会匹配题干里的“stronger”以及普通none/all-of选项。本轮改为仅遍历 `choices[i].text`，识别明确指向“其他具体选项为真且还可强化”的元陈述；返回 `has_stronger_meta`、对应的实际label和匹配的公开文本。

不要把普通“none of the above”“all of the above”全部归为更强结果元选项；不要把题干讨论更强定理也算作存在元选项。允许大小写、空白和可核查的改写，不能凭一个stronger关键词判断。

该检测默认只服务于分组和条件Skill路由，不直接改预测。若Learner学出元选项先验，由LLM依据Skill选择实际label，报告为benchmark_prior。固定输出E、使用隐藏正确label、按任务ID查表都不允许。

## 9. 离线回归：少而直接，必须覆盖曾付费出现的错误

不另造数学证明评审器。至少把下列项目纳入现有测试：

1. 原global候选能等价迁移或定向repair；含真实条件的候选不被静默改成全局；合法兄弟候选不受损。
2. EDIT可改适用性和goal；字典/列表/null错误在LLM提交边界明确返回字段路径，不出现未捕获TypeError。
3. 原Gate20和feedback12重放后，全量结果不变；实际干预2胜0负、无干预波动分别正确统计。
4. meta检测支持任意label位置；普通none/all-of和题干stronger不误判。
5. 实验快照可注入candidate但不伪造旧qualified；旧P7快照和其他benchmark照常读取。
6. 相同payload的off/on/不同policy各有独立episode scope；普通resume不重发已完成请求。
7. 真实Provider payload验证主65536/parent128000/finish16384，不被base-config旧字段覆盖。
8. 回放length、格式错、phase不足、未知HTTP、提交后崩溃和跨阶段切换；已计量的错误响应只触发既定补交，不重跑直到正确。
9. 从反馈结果到编辑、冻结、Val的完整控制流使用拦截响应跑通，低准确率不会变成runner异常或清空所有候选。

原始请求用于离线回放不是新准确率；合成响应不能算新付费完成题数。

## 10. 授权后必须真正启动并观察，不能只给命令

### 10.1 启动方式

本地Codex完成等价实现和上述离线回归后，自动记录本轮真实授权，进入付费学习及首批Train12配对。不要再停在“等待授权”，也不要因为NoSkill分数低而停。

沿用项目实际CLI并以 `--help` 验证。可以增加一个 `launch-and-observe` 入口，但下列名称只是待实现的建议，不得假称现在已经存在：

```text
prepare-revision → offline-regression → learn/repair
→ feedback（按题交错执行off和on）
→ bounded-edit（最多两轮）
→ export-experimental → val-observe → report
```

首批off/on采用按题交错执行，尽早暴露两个分支的真实问题。后续策略版本在同一预注册任务顺序下评估，不能按照早期分数挑题。相同配置的已计量NoSkill可以沿用作为固定训练基线，必须标明哪个物理响应被复用；不能重复收费或将复用计入新完成进度。

### 10.2 结束实施对话前的最低实际进度

**这是运行交付条件，不是Skill的准确率或晋升门槛。**

- 首批Train12 off/on必须 **12/12对完整完成**，两臂共24个正常、真实提交并评分的episode；实质模型生成/定向修复亦已完成，不能只有schema测试。
- 若已进入Val17，该阶段必须 **17/17完整完成** 后，才可以声称Val实施交付完成。
- 一般化要求：每个已启动的付费评估臂，若N≤20，观察全N题完成；若N>20，至少观察 `min(N,max(10,ceil(0.20*N)))` 个正常完成题。100题即每臂至少20题，不是合计20题。
- 这些题必须有完整题目身份、实际请求和raw_usage、合法答案、评分、持久化trace。**答错也算正常完成**；空答/未评分/捕获异常占位记录保留，但不算“正常完成”。
- 若窗口内出现基础设施/Schema/账本错误，修复后必须再观察每臂至少5道正常完成，且不能覆盖或删除错误记录。
- 交付前没有本轮未解决HTTP、挂起Worker、未写完的task或账本冲突；对于仍运行的大阶段，读取两次不同任务完成边界确认计数真实增长，并检查子进程没有异常退出。
- 不能用“PID存在”“已发第一条请求”“计划跑满”代替这些事实。不到标准就继续执行或明确报告阻塞，不得用成功交付措辞结束。

若环境、余额或服务故障客观阻止完成，应如实交付阻塞事实与已完成数量；这个要求不能成为隐瞒异常、无限重试或越额花费的理由。

### 10.3 中途错误与恢复

低分、no_change、合法模型拒绝是结果，正常落盘；格式/截断按现有有界finalizer处理。HTTP400属于确定的模型/请求合同结果时保存错误并定位，不盲目重试同一payload。网络超时若是否计费未知，保留最大预留，确认后再恢复；不能猜成0。

已完成episode在恢复时只读；已收到且落盘的响应从该响应继续解析；确定未发出的请求可以发出；“已发送、无最终收据”不得自动重复。修复代码后新建revision/continuation身份，不把新代码偷偷写入旧run。

进度文件用临时文件+原子rename，每题更新，不等整个阶段结束才写。至少输出：

```json
{
  "status": "running",
  "stage": "feedback",
  "phase_completed": 0,
  "phase_total": 24,
  "paired_completed": 0,
  "per_arm_completed": {"off": 0, "on": 0},
  "per_arm_normal_completed": {"off": 0, "on": 0},
  "invalid_answer_count": 0,
  "unresolved_new_requests": 0,
  "last_completed_task": null,
  "measured_tokens": 0,
  "delivery_ready": false
}
```

这里的零值只是结构例子，实际报告由产物计算。20%启动验收不能保证后80%永不报错；仍需受预算约束的持久化、错误分类及真正可恢复执行。

## 11. 预算：单题不减，运行总额不能失控

延续已确认的LiveMath累计 **45,000,000 tokens / 9,165 HTTP**，以本地最新实际账本及明确后续授权为准；文档不重置累计费用。

本轮优先使用原P7非Test阶段的未花额度。原阶段上界合计6.2M（learning0.7M、feedback2.4M、gate1.6M、val1.5M）；由于不再新增强制Gate20，可以在启动记录中把其**尚未消耗/未占用部分**分配给反馈编辑。不得挪动已计费费用，也不能把6.2M重新当作额外到账。

学习阶段原3次HTTP上限不足以容纳真实编辑和结构修复，应在本轮授权记录中明确改为最多16次物理HTTP，仍受既有token额度及9165累计请求上限约束。最多3个policy完整反馈、最多2轮实质编辑；不允许为了达到分数无限试验。

在发首个付费请求前，读取P7、HumanFrontier及其它LiveMath兄弟run账本，按物理request ID去重实际费用、保留未知费用和正在执行阶段的独占预留。本轮人工修改与P7不能各自拿同一份余额开两条满额run。默认串行完成首批观察最简单；若并行，用共享锁或不重叠的额度分配。

阶段额度要按已知逐题分布和保守余量估算，不把UTF-8字节上界说成实际tokens。若完整阶段明显无法容纳，必须在启动前决定该阶段不启动并明确缺额；不能靠降低token/task、删题、反复重置run或伪造usage让它继续。

对首批Train12配对，若按每个episode128000硬上限计算，24个episode最坏为3.072M，另加学习费用；这是风险上界，不是预期实耗。本次通常可按真实历史分布安排，但必须承认预算上界不足以保证所有异常都跑满。真实剩余低于基本安全余量时正确停机并报告，不把这种停机伪装为正常完成。
