# LiveMath learned predicate evolution

This independent derived method reuses real Train60 evidence, model-induced
predicate features, and prior learned text policies. It imports no human Bank.
It does not modify previous results, billing, plans, or promotion decisions.

## Registered finite search

For each of the two rule candidates from the first R3 induction, enumerate at
most six neighbors: delete one positive condition while keeping a nonempty
conjunction, delete one exclusion, or promote one exclusion to a positive
condition. Operations contain no domain answer strings, labels, or task IDs.
All features originate in the saved model response. Each child records its
parent, operation, and source response. These children are automatic Host edits,
not new natural model proposals. Their cards explicitly call the rule an
empirical benchmark prior, not a mathematical proof.

Run each compiled Program in the pinned Docker image. Admission uses only
Train60: at least four dispatches, accuracy at least 80%, no regression on a
historically correct task, and permutation/relabel/ambiguity checks. Select the
rule by correct count descending, regression count ascending, errors ascending,
source length ascending, then candidate ID. No Val or Test scores enter search.

Combine the best rule with three registered text alternatives: the P7-R2 best
Train12 policy, the stopped R3 first Train12 policy, and no text. Select at most
two combinations using the preexisting Train ranking. Val17 selects between
these two; it is development selection, not independent generalization.

## Exact response reuse and costs

Train feedback is zero new HTTP. Model responses can be reused only when public
task, actual Provider payload, Runtime settings, response hash, and original
metered usage match. Program dispatches execute anew and replace the model
answer only on a unique applicable match. Missing or ambiguous matches abstain.
Changed text never borrows a nearby response. Test response reuse is forbidden.

Logical per-task tokens retain original costs; newly paid costs come solely from
the cumulative ledger delta. Every reused request remains charged once in the
historical prefix. Candidate provenance additionally verifies actual original
learning response and physical request records.

## Freeze and final evaluation

Val requires at least 12/17 correct, net gain at least two, at most one regression,
no increase in empty answers, and net gain at least two on actual interventions.
Only qualified, actually consumed Programs publish. Final assets and selection
receipts are hashed before one Test100 run. Source, parameters and assets cannot
change during Test. The Test set has prior development exposure; results must
not be called an untouched blind test. Target: at least 70/100, compared with the
human reference's 80/100, without claiming statistical equivalence.

Paid authority for this derived run covers Val (1.4M tokens / 68 HTTP) and Test
(4M / 200) only. Train feedback is 0 / 0. The inherited material capacity checker
reserves a nominal 400K / 6 learning allowance, but learning HTTP is not
authorized or issued by this runner. All phases retain the cumulative 45M token
/ 9,165 HTTP ceiling, including historical conservative reservations.
