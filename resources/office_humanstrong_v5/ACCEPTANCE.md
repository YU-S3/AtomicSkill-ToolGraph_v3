## 已确认的行为

| 问题 | 验收 |
| --- | --- |
| 结果正确但提交时改百分号、单位或精度 | `computed_scalar` / `computed_list` 在真实 Docker 中读取已计算字段，格式化后原生直接提交；成功后没有额外模型改写 |
| 多层表头错列仍声称成功 | UID0192 原始源页及实际提案重放为 `header_conflict`，不产生答案，不触发 Program 最终提交 |
| 月份句点及显示单位使恢复反复失败 | UID0003 既有源页、真实选择器和规范化月份标签得到 `44463`；Docker 到评分链路通过 |
| 任意猜测超界 offset | 返回实际 source_size 与明确的越界原因；读取半行不被解析为完整数字 |
| 样本/总体、差分或分母混用 | CV/z-score 的 ddof 和变换必须显式；成对利差期序必须一致；重复百分比缩放被拒绝 |
| 多结果在解释中重新舍入/重排 | 有序列表逐项格式化、一次直接提交，符号、精度和顺序固定 |
| 新 Bank 使长题面一开始就被迫收尾 | 共享重复 Schema、按运行证据选择指导卡后，全部 102 题两臂初始请求均进入正常 Runtime，原文页逐字完整，9 个 Program 可见 |
| 无运行身份或费用记录 | V5 接入复用冻结 evaluator；真实 checkpoint、execution_manifest、请求记录及测试账本检查通过 |

旧 V3 回归最初碰到正在运行实验持有的祖先锁。测试现已与 V4 相同：把离线测试锁放在临时目录，仍使用真正 FileLock，不改动或释放生产锁；随后该用例通过。另有初期新测试夹具的浅复制和 evaluator 空题表问题已修正。原始检查记录保留，最终结果以新版 `v5_tests.xml`、`v2_v3_tests.xml` 和既有检查中的 V4 用例为准。

## 生效边界

- 修订仅位于独立 `office_humanstrong_v5` 资产与接入目录；一般方法、评分器、既有预算/重试及旧 Bank 源码未改。额外一处旧测试修改只隔离离线文件锁。
- 格式化 Program 保证显式合同的执行一致性，不替 Agent 决定题目语义。百分号约定不明确、统计口径未说明、选错业务类别仍可能产生模型错误。
- 多层表头无法可靠绑定时会拒绝，后续需要明确来源或合法计算回退；并不把拒绝伪装成答对。
- 原始 V4 三轮为 69/102、70/102、62/102，均值 65.69%。V5 尚未有新的付费准确率结果，不能宣称稳定超过 65% 或达到 70%。
- 该 Bank 参考过已有 Test 失败，属于人工参考设计，不是自然学习资产或未见 Test 评估。当前自然训练不继承它。
