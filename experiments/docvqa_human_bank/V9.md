# v9: short guidance and typed submission

The preceding GLM text-only comparison completed 201 tasks plus the same preselected
48-task repeat for each arm. Initial guidance scored 187/201 and 46/48; the Gemini
SkillOpt final text scored 182/201 and 45/48; Ours v7 text scored 185/201 and 42/48.
These exploratory results do not establish stable improvement or 95% accuracy.

This revision keeps the initial guidance as its core. The frozen Bank stores three
small clauses, with at most one selected by public question text: comparisons take
priority over titles, then quantities. The selected clauses remain real immutable
Skill assets with their own IDs. No task ID, gold answer, or result selects a rule.
There is no runtime workflow or graph execution.

Use `--skill-revision v9 --evidence-interface typed` together with `--single-node`
or `--single-node-crop`. An existing v9 Bank requires the typed interface as well.
The model chooses `verbatim`, `phone`, `page`, or `count`. Ordinary text is submitted
directly. The other types invoke the real Docker Program `typed_submit`, which
returns a `final_answer` through the existing production submission contract:

- `phone`: remove spaces in a string containing only digits and an optional leading `+`;
- `page`: remove paired dash ornaments surrounding a page number;
- `count`: remove an `N=` label from an already selected integer count.

Other values are preserved unchanged, including units, signs, names, ordinals, and
text that does not match the requested formatting contract. A printed item ordinal
is never converted into a count. The Program receives no question, gold, image or
external lookup. It does not verify the model's selected value or type.

The original model arguments, Program input/output, actual execution receipt and
final submission identity remain visible. No additional model call rewrites a
successful Program submission. A no-op format is explicitly recorded as such;
it is not evidence of accuracy improvement or naturally learned utility.

Optional image inspection retains the original image and verified crop with row
context. v9 permits an inspection only when two local execution slots remain,
leaving one slot for typed submission. Both share the existing total limit of two;
there is no new repair allowance. Older v6/v7/v8 interfaces and Banks are unchanged.

Paid comparison plan: one fresh initial-guidance Test201, followed by two Test201
runs of the same frozen v9 Bank. Freeze source, data, model parameters, budgets and
order before starting; no performance gate or prompt edits between arms. The
target is 191/201 in both candidate runs, without extra empty answers. Passing
engineering checks alone does not qualify the candidate. Report costs, correct
and wrong transitions, and both repeats even if there is no improvement.

The bank is externally authored experimental material, not a learned Ours asset.
Production scoring and general learning algorithms are untouched.
