The design's four logical areas are split into smaller source-validation,
storage and pure-matching modules to avoid importing System/runtime execution
into proof and database code. There is no new Planner, Runtime loop, model
service or fifth executable asset layer.

## Producer/consumer migration

- Atomic canonicalization and registry retrieval share full typed identity.
  Hashes remain integrity/bucket keys, not positive equivalence authority.
- Tool and Implementation alignment, replay lookup, source attribution and
  runtime route deduplication verify compatible explicit maps.
- Multi-Tool bindings are compared and bucketed by declared execution order,
  not list storage order. Duplicate order remains unproven.
- `ExtractionBatch` is consumed by System; the compatibility list API delegates
  to that single E1 request. Empty ordinary proposals do not discard a sidecar.
- New ledger events have validation, serialization, projection and lifecycle
  consumers. Registered Direct and attributed trial task sets are not added as
  raw counters; their source-identity union drives the specified threshold.
- New tables/files are covered by schema checks, knowledge digest, task
  checkpoint and freeze. Frozen loads verified snapshots without creating tables.
- Actual node/draft/task Dynamic/Rescue/continuation tools are determined before
  ContextBuilder projection. `None` native specs conservatively preserve payload.
- Main report rows carry `r103_diagnostics`; summaries retain auxiliary
  maintenance diagnostics. Raw route, proof and expression records remain
  available. Absent measurements are null, not inferred successes or zero costs.
- `run_v3_frozen_eval._verify_source_train` checks all R10.3 provenance fields.
- `runs/r103_validation/symbol_consumers.txt` records the repository-wide symbol
  search, including identity, quota, reliability, E1, prompt and freeze consumers.
