# LiveMath P3 实施与启动记录

P3 是独立的 LiveMath 方法版本 `livemath.math-capability.p3`。保留原 Train60、旧 P2/Val 结果、Bank 和费用；不重新求解 Train，不继承旧候选和晋升收据。其他 Benchmark 不启用 P3。

## 已冻结的流程

- Train60 全覆盖，按公开数学需求分为 15 个四题单元；每组最多 4 个候选，允许合法弃权。公开分析返回需求类型和精确位置，不判断正确选项。
- 每组一次提案、最多一次格式修复、一次批量内容检查。所有字段错误汇总。不同物理来源、精确引用、禁止复制答案等约束保留。
- 一次 Train-only 跨组整合，最多 8 个不同操作的候选；每个输出重新接受来源与内容检查。父候选及原始来源全部记录。真实来源但分类有争议者可进入受控效用验证。
- 跨类别覆盖优先、来源数降序、候选 ID 排序，最多 4 个进入 canonical Val 前 6 题；最多 2 个进入后 11 题。候选正文在 Val 前冻结，Val 不回流学习。
- 初筛：注入至少 3 题，净增正确至少 0，正确变错误最多 1，空答不增加。确认阶段净增正确至少 1；总注入至少 8、净增至少 2、回退最多 1、空答不增加才发布。排序依次按净增降序、回退升序、两臂总 tokens 升序、ID。此规则在付费前固定，不依结果改写。
- 同题最多注入一个 Skill；按最终晋升排名选择适用者。Val 属于开发选择成绩。Frozen 后的 Test100 需要明确复审指令；已使用这批 Test 做过开发诊断的历史保留。

## Runtime 与协议

主请求 enabled/high、65,536 completion、600 秒；Val/Test 单题父预算 128,000。仅 `length` 且无合法答案时补交一次，enabled/low、16,384 completion、无工具、零 HTTP 重试。

补交保留完整题目和选项，按实际剩余预算带入最多 16 KiB UTF-8 推理尾段，记录完整响应摘要、原推理摘要、字节起止位置。恢复使用已保存的同一份补交材料，已付费响应无需再次准入或重复请求。成功补交不再标成 `budget_censored`；预算不足、空答和首次截断分别记录。

Skill 的 guidance/applicability/card 上限分别为 512/128/1,024 字符。Schema、提示、校验和渲染同步版本化。压缩引用只按当前请求的一对一表还原，再验证真实来源和 Span；不存在的引用拒绝。合法 `no_change` 忽略不会发布的附带字段。

支持实际受限 Python Worker；有限计算结果仍不能当作一般证明。没有修改评分器或标准答案。
